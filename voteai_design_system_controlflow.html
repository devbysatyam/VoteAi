Design Philosophy
The Design Language: Civic Bold

Not pure SaaS. Not government bland. The sweet spot is Civic Bold — a design language that feels authoritative and trustworthy like a government document, but moves like a modern consumer app. Think Linear meets Aadhaar: sharp edges, high contrast, strong typographic hierarchy, with warm saffron/green/blue accent pulled from the Indian tricolor.

Sharp edges, not rounded pills

Cards use 8px radius max. Buttons use 6px. No 24px pill-shaped everything. Sharp corners signal precision and authority — right for a civic product.

border-radius: 6px (buttons), 8px (cards), 12px (modals)

High-contrast text hierarchy

3 levels of text: primary (near-black), secondary (60%), tertiary (40%). Never use more than 3 grays. Users shouldn't hunt for information.

Contrast ratio ≥ 4.5:1 for body, ≥ 3:1 for large text (WCAG AA)

Saffron + Deep Blue + Forest Green

The accent palette is the Indian tricolor abstracted: Saffron for primary actions, Deep Navy for trust/headings, Forest Green for success/completion states.

Not garish patriotism — subtle, sophisticated use of the palette

Bento grid layout

Home screen uses a bento-style card grid. Different card sizes for different information weights. Scannable at a glance. No wall of same-sized tiles.

Inspired by Apple iOS 17 widgets + Linear's dashboard

Thumb-first navigation

All primary actions in bottom 40% of screen. Top bar is read-only context. Tab bar at bottom with 5 items. No hamburger menus.

75% of users use one thumb — Steven Hoober (2025)

Motion as communication

Transitions under 300ms. Page slides in from right, back slides from left. Cards scale up from 0.96 on tap. No decorative spins.

CSS transitions only — no heavy animation libraries

Responsive Strategy
Mobile-first, Desktop-aware

Design for 375px iPhone SE first. Scale up. India's primary device for this app is a ₹8,000–15,000 Android (360–390px viewport). Every layout must look perfect there before touching desktop.

Mobile S — 320–374px (low-end Androids)

Single column. 14px horizontal padding. Compressed card heights. 11px caption text minimum. Bottom nav with icon + label. Test on this — many rural users.

Mobile M — 375–430px ★ Primary target

Single column. 16px padding. Standard card sizes. 2-col grid for feature tiles. Bottom tab nav. This is your primary design surface.

Mobile L / Foldable — 431–767px

2-column bento grid on home. Wider cards. Bottom nav preserved. Candidate cards side-by-side.

Tablet — 768–1023px

Left sidebar replaces bottom nav (64px wide, icon-only). Main content max-width 640px centred. 3-col card grid. Map takes 60% width with side panel.

Desktop — 1024px+

Left sidebar 220px with labels. Content max-width 900px. Dashboard goes 3-col bento. Map + candidate panel side-by-side. Keyboard nav fully supported.

Accessibility Checklist

Touch targets ≥ 48px

All tappable elements must be 48×48px minimum. Pad small icons. Test with fat-finger mode.

Color is never the only signal

Every status badge has text + color. Never rely on red/green alone — 8% of men are color-blind.

WCAG AA contrast

4.5:1 for body text, 3:1 for large text. Test every color combination including dark mode.

Screen reader (ARIA)

All buttons have aria-label. Images have alt text. Modals have role="dialog". Tab order is logical.

Font scaling support

Use rem/em not px for font sizes. App must not break at 200% system font size.

Multilingual layout

Hindi text is ~30% longer than English. Test all cards with Devanagari text. Never clip text.

Reduced motion

Wrap all animations in prefers-reduced-motion. Core functionality works without any animation.

Offline / low-data mode

Skeleton loaders not spinners. Cache key screens. Show stale data with timestamp rather than blank screen.
